You get an agent that has a computer. Not a chat window with plugins attached: a
Linux machine that is yours, that keeps running between conversations, and that
still holds everything the agent wrote to it the last time you talked.

So you ask for the work, not for a description of the work.

tomorrow and the file is still there, because the machine is still there.

## Who the agent is, is code

Every agent is declared in a Python file that lives in a git repository of its
own — the **harness**. This is the agent from the screenshot above, with its
prompt written inline instead of read from a file:

```python programs/splox/main.py
from splox import agent

assistant = agent(
    "Assistant",
    system_prompt="You have a Linux machine. Do the work, then say what you did.",
    model="kimi-k3",
    provider="splox",
    tools=["system:compute"],
    skills=["system:agent-browser", "system:memory"],
    max_iterations=1000,
)


def handle(msg):
    return assistant
```

Edit a line and the next message reads the new one. Nothing is parsed at publish
time, frozen into a run, or migrated afterwards: the platform asks `main.py` who
an agent is at the moment it needs to know. Push the file and every later chat
opens on the new version.

That is the shape of the whole product. The agent has a computer, the computer
has a checkout of the harness at `~/harness`, and the agent can read and edit
that checkout like any other code — including with your help, in the chat.

## What it is not

- **Not a chatbot.** It has a shell, a filesystem, a package manager, a real
  browser, and it starts programs that keep running after the tab closes.
- **Not a workflow canvas.** There are no nodes and no edges. Branching is an
  `if` in a Python file you own. If you used the old Splox, [what
  changed](/what-changed) is the map from that vocabulary to this one.
- **Not a sandbox that resets.** The disk survives. A stopped machine keeps its
  files and comes back where it left off.
- **Not tools as JSON calls.** A tool is a Python function the agent imports and
  calls in code, so one turn can chain five of them, filter the middle result and
  print only the answer. See [Tools](/build/tools).

## Who it is for

People who want an outcome and are willing to describe it once: a report
compiled from four sources, a repository audited, a scraper written and left
running, a mailbox watched. And people who want to shape how the agent works —
its prompt, its model, its tools, the points of its turn — by writing code rather
than filling in a form.

You do not have to be the second kind to use it. The account you sign up with
already has a working agent and a machine to run it on.

## Your first hour

<Steps>
  <Step title="Send a message">
    Sign in, type into the composer, and watch the tool calls appear as the agent
    works. Nothing to set up: the machine and the harness are created with the
    account. [Quickstart](/quickstart).
  </Step>
  <Step title="Give it something with a file in it">
    Ask for something that leaves a result on disk — a scraped list, a converted
    document, a script. Then open a new chat and ask it to read what it wrote.
    The point of the machine is the second half of that sentence.
  </Step>
  <Step title="Read the vocabulary">
    Six words carry the rest of this documentation: machine, harness, program,
    agent, run, chat. [Concepts](/concepts/overview) is one page that fits them
    together.
  </Step>
  <Step title="Change who the agent is">
    Ask the agent to open `~/harness`, edit the prompt or add a tool, and push.
    The next turn runs what you wrote. [Changing what your agent
    is](/build/overview).
  </Step>
</Steps>
